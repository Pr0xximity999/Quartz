Activity diagrams is, just like [[20 - 39 School/25 - Informatica/25.04 - Use Cases and Diagrams|use case diagrams]] and [[20 - 39 School/25 - Informatica/25.07 - Class Diagrams|class diagrams]], part of the Unified Modeling Language (or UML).
Activity diagrams help visualising workflows, processes or activities within a system. They show how parts of a system move and how one thing connects to another.

>[!info] Oh yeah, why don't you cite a source?
> The source of the activity diagram information i used can be found [here](https://www.geeksforgeeks.org/unified-modeling-language-uml-activity-diagrams/)

# What are activity diagrams
Activity diagrams are a way to show the steps of how a system works. They will be displayed in what order they play out and whether things occur at the same time, or one after the other (concurrent or sequential). They start and end at a single point.

The initial state is where the process starts. It marks the entry point<br>Only one initial state exists unless there are nested activities.

## 2. Action or Activity state
![[00 - 09 Vault Administration/02 - Attachments/6vl90r8a.bmp]]
<sub>source: geeksforgeeks.org</sub>

An activity represents the execution of an action either on or by objects. It it shown by a rounded rectangle. Basically every action or event that takes place is represented by an activity.
>[!example]-
>![[00 - 09 Vault Administration/02 - Attachments/Pasted image 20241205104640.png]]

## 3. Action flow or control flows
![control-flow](https://media.geeksforgeeks.org/wp-content/uploads/20240112153209/control-flow.jpg)
<sub>source: geeksforgeeks.org</sub>

Action or control flows are also referred to as paths and edges. They are used to show the transition from one point to the other using a line with an arrow head. If there is some rule or constraint to be adhered to, it will be mentioned on the arrow.
>[!example]-
>![[00 - 09 Vault Administration/02 - Attachments/Pasted image 20241205105404.png]]


## 4. Decision node and branching
![decision-node](https://media.geeksforgeeks.org/wp-content/uploads/20240112153442/decision-node.jpg)
<sub>source: geeksforgeeks.org</sub>

Decision nodes are used for, you guessed it, decisions. Whenever some choice has to be made, the decision node will be used. The outgoing arrows from the decision node can be labelled with conditions or guard expressions. These nodes always have two or more output arrows.
>[!example]-
>![[00 - 09 Vault Administration/02 - Attachments/Pasted image 20241205105903.png]]

## 5. Guards
![guard](https://media.geeksforgeeks.org/wp-content/uploads/20240112153635/guard.jpg)
<sub>source: geeksforgeeks.org</sub>


A guard refers to a statement that is sometimes written next to a decision node on an arrow within a square bracket. This decides whether the flow will go one or the other way.
>[!example]- 
>![[00 - 09 Vault Administration/02 - Attachments/Pasted image 20241205110446.png]]


## 6. Fork
![fork](https://media.geeksforgeeks.org/wp-content/uploads/20240112153718/fork.jpg)
<sub>source: geeksforgeeks.org</sub>
Forks represent a split in the flow that runs both paths at the same time (concurrent). No decision will be made before the split. A fork is represented by a black bar with one arrow going in and two or more arrows going out.

>[!example]-
>![[00 - 09 Vault Administration/02 - Attachments/Pasted image 20241205111240.png]]
>I am so good at making examples



## 7. Join
![join](https://media.geeksforgeeks.org/wp-content/uploads/20240112153918/join.jpg)
<sub>source: geeksforgeeks.org</sub>

A join is basically a fork, but instead of arrows going out, the flow joins back into one line again. They look the same as forks, but inversed.

## 8. Merge or Merge events
![merge](https://media.geeksforgeeks.org/wp-content/uploads/20240112154039/merge.jpg)
<sub>source: geeksforgeeks.org</sub>

A merge is a join statement for flows that do no run concurrently. If you for example have a decision node that splits into two paths, converging those paths together would use a merge node and not a join.
>[!example]-
>![[00 - 09 Vault Administration/02 - Attachments/Pasted image 20241205111809.png]]


## 9. Swimlanes
![swimlane](https://media.geeksforgeeks.org/wp-content/uploads/20240112154155/swimlane.jpg)
<sub>source: geeksforgeeks.org</sub>

Swimlanes are used to group together related activity into one column or row. They can be horizontal and vertical. Swimlanes are optional, but they are used to add modularity to the diagram, though they are a recommended good practice. It is more used as a visual aid instead of adding functionality. Swimlanes are represented by a bar with two lines sticking out.
>[!example]-
>![[00 - 09 Vault Administration/02 - Attachments/Pasted image 20241205112335.png]]
>Bad example, but you get the gist of it.


## 10. Time event
![time-event](https://media.geeksforgeeks.org/wp-content/uploads/20240112154305/time-event.jpg)
<sub>source: geeksforgeeks.org</sub>

A time event is represented by an hourglass and means a flow will be stopped for some time. If you for example have a database request that takes some time to complete, you can add a time event.
>[!example]-
>![[00 - 09 Vault Administration/02 - Attachments/Pasted image 20241205112630.png]]

## 11. Final state or End state
The final state in the system is when every activity ends. It is represented by a red circle with a filled circle inside. A system or process can have multiple final states.
