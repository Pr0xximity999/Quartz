# Intro
Voor een goed project is het belangrijk dat je duidelijke requirements opstelt, zodat je er tijden en prioriteiten aan kan hangen. Daarnaast is het ook handig omdat iedereen dan op 1 lijn staat met wat er moet gebeuren, en dat het voor de stakeholders in leesbare taal staat.

# Doel
Voor welk doel wil je een requirement gebruiken? Wat moet het uiteindelijk doen? 

# Fidelity
Hoe hoog moet je fidelity (getrouwheid) zijn? Hoe realistisch of in depth is je model en simulatie.

# Determinisme
In hoeverre krijg je dezelfde gedrag met dezelfde input. Als je een AI model gebruikt kan dit iedere keer weer anders zijn. Denk hier goed over na hoe deterministisch functionaliteit word.

# Platform
Waarop moet de applicatie draaien? Op pc, of telefoon?

# Externe factoren
Moet het met externe resources interfacen zoals een API of MQTT service?

# Requirements
Een requirement is een concrete omschrijving van wat een systeem moet doen, hebben of waarvan het moet voldoem om waarde te leveren aan de gebruiker/opdrachtgever.

Een goede requirement:
- Is duidelijk en conceet
- Beschrijft een aspect
#nog-af-maken 

Voor requirements moeten ook **criteria** opgesteld worden. Hier staat in wanneer deze requirement behaalt is.

Maak requirements en criteria over:
- De simulatie
- Het AI model / Reinforcement learning model
- Non-functional requirements
